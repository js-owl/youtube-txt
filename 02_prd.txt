Product Requirements Document (PRD) — Frontend & UI/UX
1. Обзор продукта
Название (рабочее): TubeSum (или YTSummary)
Концепция: Максимально простой, быстрый и одностраничный веб-сервис. Пользователь вставляет ссылку на YouTube — получает структурированный текстовый конспект.
Платформа хостинга: Vercel (Hobby / Бесплатный тариф).
Подход к дизайну: Минимализм, фокус на контенте, отсутствие лишнего визуального шума (в стиле Notion или самого Vercel).
2. Пользовательский путь (User Flow)
Пользователь заходит на сайт (один главный экран).
Видит крупный заголовок и поле ввода.
Вставляет ссылку на YouTube-видео и нажимает «Создать саммари» (Enter).
Видит минималистичную анимацию загрузки.
Получает готовый текст (с возможностью скопировать его в буфер обмена одним кликом).
3. Дизайн-система
3.1. Цветовая палитра (Светлая тема)
Дизайн строится на монохромной базе с одним акцентным цветом, чтобы не отвлекать от чтения.
Фон страницы: #FAFAFA (Светло-серый, почти белый, снижает нагрузку на глаза).
Основной текст: #171717 (Темно-серый/черный).
Вторичный текст (подсказки, плейсхолдеры): #737373.
Фон контейнеров (карточек/инпутов): #FFFFFF.
Границы (бордеры): #E5E5E5.
Акцентный цвет (Кнопка, фокус инпута): #000000 (Черный) или #2563EB (Спокойный синий).
Цвет ошибки: #EF4444 (Красный, приглушенный).
3.2. Типографика
Шрифт: Inter, Roboto или системный (San Francisco на Mac/iOS, Segoe UI на Windows). Sans-serif без засечек.
Заголовок H1: 36px - 48px, Font-weight: 700 (Bold). Tracking (межбуквенный интервал): слегка уменьшенный (-0.02em).
Основной текст (результат): 16px - 18px, Font-weight: 400 (Regular), Line-height: 1.6 (для комфортного чтения).
Текст кнопки/инпута: 16px, Font-weight: 500 (Medium).
3.3. Стилизация элементов (UI-кит)
Скругления (Border Radius): Слегка скругленные углы — 8px или 12px (современный мягкий минимализм).
Тени: Едва заметные для инпута и плавающих элементов: box-shadow: 0 4px 6px -1px rgba(0, 0, 0, 0.05).
Анимации: Мягкие переходы состояний (hover, focus, активная кнопка). transition: all 0.2s ease-in-out.
4. Структура интерфейса (Layout)
Приложение состоит из одной страницы. Весь контент центрирован. Максимальная ширина контейнера (Max-width): 800px (оптимально для чтения длинных текстов).
4.1. Шапка (Header) - опционально
Логотип (просто текстовый: TubeSum).
Ссылка на GitHub проекта (небольшая иконка справа).
4.2. Главный блок (Hero & Input)
Заголовок: «Суть видео за пару секунд».
Подзаголовок: «Вставьте ссылку на YouTube-видео, чтобы получить краткое содержание».
Поле ввода (Input):
Большое, заметное.
Плейсхолдер: https://www.youtube.com/watch?v=...
При фокусе: появляется четкая рамка акцентного цвета.
Кнопка:
Текст: «Сделать саммари» (или иконка стрелки для экономии места).
Состояние при наведении (Hover): небольшое затемнение или инверсия.
Расположение: либо справа внутри поля ввода, либо под ним на всю ширину (для мобилок).
4.3. Блок результата (Output Area)
Появляется под полем ввода после успешной загрузки.
Включает миниатюру видео (Thumbnail) и его название (мелким шрифтом) — для подтверждения, что видео распознано верно.
Текст саммари: Отформатирован с помощью Markdown (списки, жирный шрифт для ключевых мыслей).
Кнопка «Скопировать»: Небольшая иконка (Clipboard) в правом верхнем углу блока с текстом. При клике меняется на иконку галочки (Success) на 2 секунды.
5. Состояния интерфейса
Начальное (Empty State): Только заголовок и поле ввода. Блока результатов нет.
Загрузка (Loading State):
Кнопка блокируется (Disabled), текст меняется на «Генерация...» или появляется спиннер внутри кнопки.
В блоке результата отображается "Скелетон" (Skeleton loader) — пульсирующие серые полоски, имитирующие текст.
Успех (Success State): Плавное (Fade-in) появление блока с текстом саммари.
Ошибка (Error State):
Текст ошибки появляется под полем ввода красным цветом (например: "Неверная ссылка", "Видео слишком длинное", "Субтитры не найдены").
Поле ввода подсвечивается красной рамкой.
6. Требования к верстке и Vercel
6.1. Адаптивность (Responsive Design)
Mobile-First подход: На мобильных устройствах поле ввода и кнопка выстраиваются друг под другом. Отступы (padding) по краям экрана не менее 16px.
Desktop: Поле ввода и кнопка на одной линии (flex-row), контент по центру экрана.
6.2. Технологический стек (рекомендация для UI)
Фреймворк: React (Next.js) — идеально ложится на бесплатный тариф Vercel.
Стилизация: Tailwind CSS (отлично подходит для создания описанного дизайна без написания кастомного CSS, позволяет легко настраивать цвета и отступы).
Иконки: Lucide Icons или Heroicons (минималистичные SVG-иконки).
6.3. Оптимизация под бесплатный тариф Vercel (Hobby)
Статика: Максимально легкий бандл. Использовать системные шрифты или оптимизированную загрузку Google Fonts через next/font, чтобы не было прыжков верстки.
Edge/Serverless Limits: Поскольку бэкенд будет крутиться на serverless-функциях Vercel, на фронтенде обязательно нужно предусмотреть обработку таймаута (на бесплатном тарифе функция обрывается через 10-60 секунд). Если саммари генерируется долго, UI должен корректно сообщить пользователю об ошибке по таймауту.
